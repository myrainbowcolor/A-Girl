## Context

See proposal.md - Why。scene_first 路径优先调用 `compose_contextual_reply`；未命中分支时落入问卷式 open 兜底。`mock.py` 对未覆盖关键词常返回空串。既有短句低落含「灰心」但不匹配「心灰」；不含「心死」「麻了」「麻木」。

## Goals / Non-Goals

**Goals:**
- ≤12 字心灰/心死/麻了/麻木短句命中专用共情分支
- compose 与 mock 话术对齐
- 既有「灰心了」「心凉了」与短句低落路径回归通过
- 最小 diff，可测可回滚

**Non-Goals:**
- 不改调度频率、安全策略、avatar、记忆/编排主路径
- 不把「心死」纳入危机关键词（避免误报热线）
- 不新增 dialogue_quality 场景（基线已 26/26）
- 不扩其他未点名缺口

## Decisions

1. **关键词**：`心灰` / `心死` / `麻了` / `麻木`（用「麻了」「麻木」整词，避免单独「麻」误伤「麻烦」等）。
2. **位置**：置于心凉/寒心/受够了分支之后、通用 open / 短句低落之前；「灰心了」仍由既有短句低落命中。
3. **分流**：按「心死」「麻了/麻木」「心灰」轻分流话术，避免单一 `_pick` 混搭。
4. **语气**：接住心灰的泄气感、心死的空落感或麻木感，至多一个问句；不以「嗯」开头；不说教；不输出危机热线。
5. **mock**：同步场景分支；`_VENT` / `_user_tone` 补充同关键词，便于倾诉语气一致。

## Risks / Trade-offs

- [与灰心混淆] 「心灰」≠「灰心」→ 独立关键词，勿依赖「灰心」子串
- [危机误报] 「心死」口语 ≠ 自伤 → 不改 `safety.py`，话术走陪伴共情
- [「麻了」过宽] 限制 ≤12 字 + 整词「麻了/麻木」，降低误伤
- [话术混搭] 单池乱抽 → 按关键词分流
