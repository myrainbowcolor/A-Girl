## Context

失业/裁员短句当前无专用 compose 分支：「被裁了」等返回 `None` 落入 open 兜底；「丢工作了」因含「工作」命中通用工作话题分支，话术偏离失业语境。见 proposal.md - Why。沿用既有短句失利分支模式（考试/面试失利），单点补齐。

架构参考：`docs/ARCHITECTURE.md` 中人格与编排分层；本改动仅触及 deterministic compose / mock 场景分支，不改 orchestrator 主路径。

## Goals / Non-Goals

**Goals**
- ≤12 字含被裁/裁员/被开除/失业/丢工作的短句走裁员共情，非 open 兜底
- 「丢工作了」优先于通用工作话题分支，避免误路由
- compose 与 mock 场景路径对齐

**Non-Goals**
- 不扩展「被鸽 / 愧疚 / 摆烂 / 内疚」等其他缺口
- 不改调度频率、安全策略、记忆召回、avatar 映射
- 不改动加班疲惫、冲动辞职、辞职信、工作话题（非失业）既有路径语义

## Decisions

1. **独立短句分支，置于工作话题之前**：在 `compose_contextual_reply` 中，于「工作上的事 / 工作/上班」通用短句分支**之前**插入 ≤12 字失业/裁员分支，关键词：`被裁`、`裁员`、`被开除`、`失业`、`丢工作`。这样「丢工作了」不会落入「忙不过来 / 不公平」话术。
2. **按关键词轻分流**：被裁/裁员、开除、失业、丢工作可略有话术差异，但统一先接住失落、陪着听，至多一个问句；禁止「下次加油」灌鸡汤与「嗯」开头。
3. **mock 对齐**：`mock.py` 在对应工作话题分支之前同步同条件分支，保证 CI 确定性。
4. **回归保护**：保留 `test_compose_work_topic` 等既有用例，确保「工作上的事」仍走原路径。

## Risks / Trade-offs

- [长句「我昨天突然被裁了心里好乱」>12 字] → 本轮仅覆盖 ≤12 字；更长句依赖 LLM/persona 侧重或通用负面
- [「裁」单字误伤] → 使用「被裁」「裁员」完整词，避免单字「裁」
- [「丢工作了」与工作话题抢占] → 明确失业分支在前，并加回归断言禁止「忙不过来/不公平」

## Migration Plan

纯后端逻辑修正，无 DB/API 变更。回滚即 revert compose/mock/tests 改动。
