## Context

`compose_contextual_reply` 是 scene_first 编排的优先无 LLM 接话路径。近期已补齐低落/疲惫/困倦等短句，但探测发现青少年高频口语「无语」「尴尬」「社死」整句或短句（≤12 字）仍返回 `None`，落入问卷式 open 兜底（「你想从哪儿开始说？」「随便丢几个词」），缺少先接住无语/尴尬感的共情。

## Goals / Non-Goals

**Goals**
- 在通用 open 兜底之前新增短句无语/尴尬/社死分支，先接住情绪，至多一个轻问
- mock 场景分支与 compose 对齐，保证基线评测与生产路径一致

**Non-Goals**
- 不扩展到「服了」「摆烂」等其他网络俚语（本轮仅无语/尴尬/社死簇）
- 不改调度频率、安全策略、记忆召回、avatar 映射

## Decisions

1. **独立短句分支**：不并入通用「短句低落」关键词表——无语/尴尬语气偏社交尴尬而非纯悲伤；专属回复更贴切（「无语的时候真的憋屈」「尴尬的感觉我懂」）。
2. **匹配范围**：`len(text) <= 12` 且含「无语」「尴尬」「社死」任一；放在短句低落倾诉附近、通用 open 兜底之前。
3. **mock 对齐**：在 `_scene_reply` 增加同关键词短句分支，语气与 compose 一致，避免 mock 走通用问卷/无关模板。

## Risks / Trade-offs

- [长句含「无语」误伤] → 限制 len≤12，长句仍走其他场景/LLM
- [与愤怒「气死」分支重叠] → 本簇不含「气」，不抢愤怒分支

## Migration Plan

纯后端逻辑扩展，无 DB/API 变更。回滚即 revert compose/mock 改动。
