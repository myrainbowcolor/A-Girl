## Context

See proposal.md - Why。scene_first 路径优先调用 `compose_contextual_reply`；未命中分支时落入问卷式 open 兜底。`mock.py` 对未覆盖关键词常返回空串。既有失恋/吵架分支关键词不含「被鸽/放鸽子/爽约」。

## Goals / Non-Goals

**Goals:**
- ≤12 字被鸽/放鸽子/爽约短句命中专用共情分支
- compose 与 mock 话术对齐
- 最小 diff，可测可回滚

**Non-Goals:**
- 不改调度频率、安全策略、avatar、记忆/编排主路径
- 不扩「愧疚/摆烂/内疚」等其他缺口
- 不新增 dialogue_quality 场景（基线已 26/26）

## Decisions

1. **关键词**：`被鸽` / `放鸽子` / `放我鸽子` / `爽约`；不用单独「鸽子」（易误伤）。
2. **位置**：置于通用 open 兜底与短句低落倾诉之前；与失恋/吵架关键词互不重叠，顺序风险低。
3. **分流**：按「爽约」「放鸽子/放我鸽子」「被鸽」轻分流话术，避免单一 `_pick` 混搭导致「被鸽了」抽到「爽约」话术。
4. **语气**：接住被放鸽子的失落与委屈，至多一个问句；不以「嗯」开头；不套用分手/失恋话术。

## Risks / Trade-offs

- [误伤] 「鸽子」单独词 → 仅用「被鸽/放鸽子/放我鸽子」组合
- [话术混搭] 单池乱抽 → 按关键词分流
- [与失恋混淆] 用户说「被前男友放鸽子」含分手语境但 ≤12 字短句通常不含；长句仍走既有路径，可接受
